# M4 — Python Ecosystem Resolver and Django Priors

Date: 2026-09-12
Status: implemented. Exit criteria 1–3 met; criterion 4 is this section's
record in `code_arch_architecture.md`. Live-agent runs stay credit-gated.
Implements: `code_arch_architecture.md` M4 ("two ecosystems supported
properly") plus the Django half of M3 deferred for want of a parser.
Evidence: flask-sqlalchemy (`src/` layout, relative imports) and
gothinkster/django-realworld-example-app pinned at
29c9d42 (project + 4 apps, relative + third-party + `include()` wiring).

## Problem

The tool hard-errors on Python repositories (`no JavaScript or TypeScript
source files found`). The M4 exit needs TypeScript *and* Python supported
properly, measured on real checkouts — not fixtures. Two local checkouts
cover the spread: flask-sqlalchemy (src-layout package, relative
intra-package imports, stdlib, `__future__`, third-party) and realworld
(Django project + apps, `models/views/urls/serializers`, migrations,
`include('conduit.apps.articles.urls')` string wiring invisible to import
parsing).

## Goals

- `.py` end to end: inventory, parse, resolve, profile, rank, flows, render.
- Python package semantics: dotted paths, relative depth, `__init__.py` and
  namespace packages, src-layout roots.
- Django priors: detection, `urls.py`/`manage.py`/`wsgi.py` entries,
  `include()` string edges.
- Measured resolution rates on three Python checkouts; determinism; budget.

## Non-goals

- Type-directed resolution (which `x` a name binds to). Stage 2 reports the
  specifier; stage 3 maps it to a file. Unchanged.
- `__all__`-based export tracking. Python has no export keyword; every
  symbol reads `exported=false`, documented at the site.
- Re-export-chain following beyond file edges (same as TS).
- A Python label model or Python-specific naming. Derived names read dirs
  and identifiers in any language.
- Precomputed transitive closure; cross-cluster flows (prior rejections
  stand).

## Design

### Phase 1 — inventory and types (`types.rs`, `inventory.rs`)

`Language::Python` from `.py`. `is_test` gains `test_*.py`, `*_test.py`,
`conftest.py` basenames. `VENDOR_DIRS` gains `__pycache__`, `.venv`,
`venv`, `env`, `.tox`, `site-packages`. `GENERATED_MARKERS` gains
`Generated by Django` (migrations are snapshots, not architecture).
`ExcludeStats.non_js_ts` is renamed (render text follows); it counted
"everything else" since before M4.

### Phase 2 — parse (`parse.rs`, `Cargo.toml`)

`tree-sitter-python` dependency; `Parsers` gains a Python parser. The
node-kind table (not `.scm` queries, per the stage-2 rationale) gains:

```text
import_statement          `import a.b as c` → specifier `a.b` (one ref per name)
import_from_statement     `from .x import y` → `.x`; `from . import y` → `.`;
                          `from ..pkg import z` → `..pkg`; absolute kept dotted
function_definition       SymbolKind::Function via `name` field
class_definition          SymbolKind::Class via `name` field
call_expression           callee `include` + first-arg string → marked ref (phase 5)
```

Relative-level reconstruction reads the `relative_import`/`level` shape of
the grammar: N leading dots + module, or N dots alone. `exported` is always
false. `is_interesting_symbol` applies unchanged (dunder methods like
`__str__` pass the length rule; `__init__` constructors are as uninformative
as TS `constructor` and are filtered by name).

### Phase 3 — resolve (`resolve.rs`)

Specifier forms: dotted absolute (`a.b.c`), dot-relative (`.x`, `..pkg`,
`.`), plus all existing TS forms (disjoint by language: only Python files
emit dotted specs, only TS files emit bare/aliased ones).

```text
dotted      try each root: <root>/a/b/c.py, <root>/a/b/c/__init__.py
relative    importer package = importer's dir if it holds __init__.py else
            the dir itself, walked up N-1 levels; then the dotted rule
roots       project root, plus <root>/src when a src-layout package is
            detected (<root>/src/*/__init__.py exists)
```

Internal lookup precedes the external heuristic (the M3 rule, unchanged
shape). `__future__` is always external, never an unresolved miss. Relative
misses stay unresolved and count in the rate. No `__init__.py` requirement
anywhere (namespace packages resolve by path existence).

Accepted collision, same as M3: a stdlib/third-party name matching a repo
file resolves to the repo file.

### Phase 4 — profile (`profile.rs`)

`pyproject.toml` (`[project] name/dependencies`, `[tool.poetry.*]`
fallback) and `requirements*.txt` supply name + deps. Framework table gains
`django → Django`, `flask → Flask`, `sqlalchemy → SQLAlchemy`,
`djangorestframework → DRF`. Django detection: dep, `manage.py` present, or
`DJANGO_SETTINGS_MODULE` in `manage.py`. Entry hints: every `urls.py`
(`urls <app-dir>`), `manage.py` (`manage`), `wsgi.py`/`asgi.py`. Views and
models stay targets.

### Phase 5 — `include()` edges (parse + resolve)

In `.py` files only, `include('<dotted>')` first-arg strings are emitted as
`django-include:<dotted>` refs. Resolve strips the marker and applies the
dotted rule. The marker keeps parse profile-free and the edge kind explicit;
JS `include()` is untouched, and bare-Python `include(` outside Django is
near-nonexistent (`include` is not a builtin). Non-dotted strings
(`r'^api/'` patterns, namespaced `include(x, namespace=)`) yield nothing —
only the first-arg string that parses as a dotted path.

### Stages 6–10

Unchanged code. Leiden, churn, confidence, flows, labels and render are
language-agnostic over file ids; flows traverse whatever out-edges resolve.
`run.py` `SOURCE_SUFFIXES` gains `.py`.

## Testing

Hermetic. No Django checkout, no network in the default suite (real
checkouts stay pinned under gitignored `eval/repos/`):

- Inventory: `.py` collected with `Language::Python`; `test_foo.py`,
  `foo_test.py`, `conftest.py` test-classed; `__pycache__`/`.venv`
  excluded; migration text generated-classed.
- Parse: `import a.b as c` (one ref per dotted name), `from .x import y`,
  `from . import y`, `from ..pkg import z`, `from __future__ import ...`
  (specifier kept; resolve externals it), def/class symbols, `include()`
  marker emission and non-marking of other callees, broken source partial.
- Resolve: dotted file vs package dir, relative depth incl. `from . import`,
  src-layout roots, namespace package without `__init__.py`, miss →
  unresolved, stdlib/third-party → external, `__future__` → external.
- Profile: pyproject + requirements parsing, Django detection three ways,
  `urls.py`/`manage.py` hints, non-Django repos unaffected.
- Determinism: byte-identical reruns on fixtures (existing pattern).

A Django-layout fixture under `eval/fixtures/` exercises entries end to end
without a checkout. Fixture *content* (`tasks.json` corpora) is untouched —
only additive files, so M1 task sets do not move.

## Exit criteria

1. `cargo test` (existing unmodified + new) and `python -m pytest eval` pass.
2. Python checkouts map with measured resolution (target: ≥90% on all three;
   anything lower is written down with the miss list, not averaged away);
   TS checkouts unchanged.
3. Django entries + ≥1 flow on realworld; budget and determinism hold.
4. Results in `code_arch_architecture.md` win or loss.

## Risks

**Src-layout detection misfires.** A repo with an unrelated `src/` dir
containing no packages adds a harmless extra root (lookups miss, fall
through). A repo whose packages live *only* under `src/` without the
marker file is missed — namespace src-layout. Mitigation: the miss list is
inspected per checkout in measurement.

**`include()` strings overreach.** A non-Django `include('a.b')` would forge
an edge. `include` is not a Python builtin and the dotted-path shape check
rejects URL patterns; the residual risk is a same-named helper, accepted
and documented.

**Treating `exported=false` everywhere weakens symbol display.** Labels use
top symbols regardless of flags today; if a gap shows, it shows in review,
not silently.
