# Query interface: serve the indexes as lookups

Date: 2026-09-16. Status: ready to implement. No model calls, no spend.

## Why

Every positive result so far came from lookups served to the agent, never from the map
as text:

| Benchmark | Lookup | Result |
|---|---|---|
| M1v2 navigation (Hono, Commerce, TypeDI) | `importers(path)` | F1 +0.37 vs no map (`eval/results-nav-importers/`) |
| Cross-language impact (paperless-ngx) | `route_callers(view)` + `importers(path)` | F1 1.00 vs 0.874, 8/8 exact (`eval/results-xlang-routes-fixed/`) |
| Same tasks, map in context | none | null or negative (`eval/results-nav-3arm/`, `eval/results-xlang-36flash-paid/`) |

Those lookups exist only inside the eval harness (`eval/run.py` `Session`). `codearch`
writes `.codearch/imports.md` and `.codearch/routes.md`, but a real agent reading those
files is the setup that did not help. This work gives agents the lookups directly.

## Scope

| Part | What | Size |
|---|---|---|
| **A** | `codearch importers <file>` and `codearch callers <View>` CLI subcommands | ~150 lines + tests |
| **B** | Tell agents the commands exist (map sentence + README) | tiny |
| **C** | `codearch mcp`: the same two lookups as MCP tools over stdio | ~250 lines + tests |

Do A and B first and commit them. C is a separate step; it must not start until A's gates
pass.

Out of scope: rebuilding the index on query, watching files, new lookup kinds, any
network access.

## Acceptance gates

1. `codearch .` and every existing flag behave exactly as before. All existing tests pass
   unchanged, except render tests that assert the Imports section text (B changes it on
   purpose; update those assertions and nothing else).
2. **Parity with the measured lookups.** On the pinned eval checkouts, `codearch importers`
   returns the same set and depths as `build_tasks_nav.importers` over the same
   `imports.md`, and `codearch callers` the same list as `run_agent.parse_routes`, for
   every task in `tasks-nav-gated.json` and `tasks-xlang.json` (step A5).
3. Queries never write anything and never re-analyze the repository.
4. `cargo test` and `python -m pytest -q eval/test_*.py` pass.
5. For C: a scripted stdio session (initialize → tools/list → tools/call for both tools)
   passes as a Rust test, and one manual check with a real MCP client is recorded in this
   file.

## What exists today (read before starting)

`.codearch/imports.md`, written by `render::import_index` (`src/render.rs`): a header,
then one line per imported file.

```text
# Reverse Import Index — paperless-ngx

Generated by Code Arch. For each file, every analyzed file that imports it.
3019 imports into 363 files · import resolution 77% · 1259 unresolved specifiers carry no edge.
External packages are not listed. Files nothing imports are omitted.

src-ui/src/app/app.component.ts ← src-ui/src/app/app.component.spec.ts, src-ui/src/main.ts
```

`.codearch/routes.md`, written by `contract::routes_markdown` (`src/contract.rs`), only
when route links exist:

```text
# Route callers

Backend views and the frontend files whose request strings name every segment ...

## `BulkEditObjectsView` — `src/documents/views.py`

Routes: `bulk_edit_objects`

- `src-ui/src/app/services/rest/abstract-name-filter-service.ts`
```

The transitive walk the eval measured is `importers` in `eval/build_tasks_nav.py`:
breadth-first over the reverse index, each file recorded once at the smallest hop count,
the target itself never listed. Port that behaviour exactly.

The CLI (`src/main.rs`) is a single clap `Parser` with a positional `path` (default `.`)
and options. The state directory is `<repo>/.codearch` unless `--codearch-dir` is given.

## Part A: CLI subcommands

### A1. Module `src/query.rs`

One job: answer lookups from the index files. No analysis, no writing.

```rust
/// Reverse import index: imported file -> its direct importers, in file order.
pub fn parse_imports(markdown: &str) -> BTreeMap<String, Vec<String>>;
/// Route index: view name -> every section naming that view.
pub fn parse_routes(markdown: &str) -> BTreeMap<String, Vec<RouteEntry>>;
/// Transitive importers with hop counts; target excluded; smallest depth wins.
pub fn importers(index: &BTreeMap<String, Vec<String>>, target: &str, max_depth: Option<usize>)
    -> Vec<(String, usize)>;   // sorted by (depth, path)
```

- Parse only the line shapes above; skip header and prose lines. A line containing
  ` ← ` is an index line; split its importers on `, `.
- Paths in both files are repository-relative with `/` separators.
- A view name can appear in more than one section (`route_join` skips ambiguous class
  names today, but do not rely on it), so keep every section and print all of them.

**Round-trip tests** (the strongest check that the parser matches the writer): build a
small inventory and edge set, render with `render::import_index` and
`contract::routes_markdown`, parse back, and assert equality. If the writer ever changes
format, these tests fail in the same commit.

Walk tests: a three-file chain (depths 1 and 2), a cycle (terminates, target not listed),
`max_depth = 1`.

### A2. CLI shape

```text
codearch [PATH] [OPTIONS]                        # unchanged
codearch importers <FILE> [--depth N] [--json] [--repo PATH] [--codearch-dir DIR]
codearch callers <VIEW> [--json] [--repo PATH] [--codearch-dir DIR]
```

- Use an optional clap subcommand beside the existing arguments, with
  `args_conflicts_with_subcommands = true`. Test that `codearch .`, `codearch src` and
  `codearch --no-git eval/fixtures/xlang` still parse as analysis runs.
- **Ambiguity rule:** a directory literally named `importers` or `callers` must still be
  analyzable. Document `codearch ./importers` as the way to do it, and add a test.
- `--repo` defaults to `.`. The index is read from `--codearch-dir` or `<repo>/.codearch`.

### A3. Input normalization

`<FILE>` arrives in whatever form an agent has: `src/a.ts`, `./src/a.ts`, `src\a.ts`,
or an absolute path inside the repo. Normalize to the index's form: strip `./`, convert
`\` to `/`, and make absolute paths relative to `--repo` (canonicalize both sides first).
A path outside the repo is an error, not an empty result.

### A4. Output and exit codes

Plain text by default, one result per line, so shell agents can read it:

```text
$ codearch importers src/app/services/rest/tag.service.ts
1  src/app/components/manage/tag-list/tag-list.component.ts
1  src/app/pipes/tag-name.pipe.ts
2  src/app/components/manage/tag-list/tag-list.component.spec.ts
```

```text
$ codearch callers TagViewSet
src/documents/views.py  (routes: tags)
  src-ui/src/app/services/rest/tag.service.ts
```

(Illustrative output; take real paths from the index.)

`--json` prints one object: `{"target": ..., "importers": [{"path": ..., "depth": ...}]}`
or `{"view": ..., "matches": [{"file": ..., "routes": [...], "callers": [...]}]}`.
Match the eval tool's observation shape (`eval/run.py`) so results stay comparable.

| Case | stdout | stderr | Exit |
|---|---|---|---|
| Results found | results | index age line (below) | 0 |
| File/view not in index | nothing (`[]` in JSON) | a one-line reason | 0 |
| Index file missing | nothing | `no .codearch/imports.md under <dir>; run codearch <repo> first` | 2 |
| Path outside repo, bad arguments | nothing | error | 2 |

Reasons for a miss, stated once, not guessed. For `importers`: "nothing imports it, or it
was not analyzed". For `callers`: up to 5 indexed view names that contain the query
case-insensitively (`callers tag` → `TagViewSet`), then "or no route in the index names
this view".

**Staleness:** print to stderr `index written <N> minutes ago` from the index file's
modification time. Do not re-analyze and do not compare source mtimes; an agent that sees
an old index can run `codearch` itself.

### A5. Parity check against the measured lookups (gate 2)

Add `eval/check_query_parity.py`. For each repo used by `tasks-nav-gated.json` and
`tasks-xlang.json`:

1. Run `codearch <repo> --no-index --codearch-dir <tmp>` (outside the pinned checkout;
   afterwards `git -C <repo> status --porcelain` must print nothing).
2. For each task target, compare `codearch importers <target> --json --repo <repo>
   --codearch-dir <tmp>` with `build_tasks_nav.importers(parse_index(imports.md), target)`.
3. For each xlang task view, compare `codearch callers <view> --json ...` with
   `run_agent.parse_routes(routes.md)[view]`.

Print mismatches and a summary; exit 1 on any mismatch. Add a hermetic test for the
comparison logic to `eval/test_tasks_nav.py`. Record the summary line in the log below.

## Part C: MCP server (separate commit, after A)

`codearch mcp [--repo PATH] [--codearch-dir DIR]` serves the two lookups as MCP tools
over stdio, reusing `query.rs` unchanged.

**Check the current MCP specification before writing code** (modelcontextprotocol.io:
"Lifecycle", "Transports" (stdio) and "Tools"). The outline below is from memory and may
be out of date; where it differs, the spec wins, and note the difference here.

Spec check 2026-09-16 (Lifecycle, Transports, Tools, Ping, Discovery pages, all read):
the outline below holds verbatim for protocol versions 2025-11-25 and earlier. One
real difference: the newest revision (2026-07-28) removes the `initialize` handshake
entirely (stateless per-request versions in `_meta`, plus mandatory `server/discover`).
The server implements legacy handshake semantics — the only flow deployed clients
speak — for `2024-11-05`/`2025-03-26`/`2025-06-18`/`2025-11-25`, *plus* `server/discover`
advertising exactly those versions, which is the new spec's own stdio
backward-compatibility probe (a dual-era client falls back to the handshake from it).
Tool descriptions reuse the eval prompts' sentences minus the harness's
`{"tool":...}` action wrapper, which is eval syntax, not prose. Everything else below
matched the spec as written.

- Transport: newline-delimited JSON-RPC 2.0 on stdin/stdout. **Nothing but protocol
  messages on stdout**; diagnostics go to stderr.
- `initialize`: reply with a protocol version the spec lists as supported (the client's
  requested version when supported), `capabilities: {"tools": {}}`, and
  `serverInfo {name: "codearch", version: CARGO_PKG_VERSION}`.
- `notifications/initialized` and any other notification: no reply.
- `tools/list`: two tools with JSON Schema inputs:
  - `importers`: `{path: string, depth?: integer}`.
  - `route_callers`: `{view: string}`.

  Reuse the tool descriptions of the eval prompts (`eval/openrouter_agent.py`
  `IMPORTERS_TOOL`, `ROUTES_TOOL`) so the measured wording is the shipped wording.
- `tools/call`: result `content: [{type: "text", text: <the --json output>}]`. A miss is a
  normal result with the miss reason in the text. A missing index or bad arguments is
  `isError: true` with the error message as text.
- `ping`: empty result. Unknown method: JSON-RPC error `-32601`. Unparseable line:
  `-32700`. Never exit on a bad message; exit on stdin EOF.
- Use `serde_json`, already a dependency. Do not add an MCP SDK crate for two tools.
- Load the index files per call, not once at startup, so a re-run of `codearch` is picked
  up without restarting the server.

Tests:

1. Scripted session as a Rust test: feed messages to the server loop through a reader,
   collect the writer's output, and assert each response: ids echoed, both tools listed,
   one real result from a fixture index, one miss, one missing-index error, one unknown
   method error.
2. Manual check with a real client, recorded in the log, e.g.
   `claude mcp add codearch -- codearch mcp --repo <path>`; ask the agent a question that
   needs `importers` and confirm the tool call appears.

README: a "Use from an MCP client" snippet with that command.

## Rules while working

- `query.rs` reads index files only; never import analysis stages into it. If a lookup
  needs data the files do not hold, stop and record it here rather than re-analyzing.
- Keep output byte-deterministic (sorted as specified) so tests and agents see stable
  answers.
- One commit per part (A+B, then C). The message states which gates were checked.
- If gate 2 fails, the port is wrong: fix `query.rs` until parity holds. Do not change the
  eval's Python walk to match.
